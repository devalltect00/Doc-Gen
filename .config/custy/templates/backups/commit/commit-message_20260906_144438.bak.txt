feat(doc-gen)!: checkpoint the Doc Gen 1.0 redesign foundation

Checkpoint the Doc Gen 1.0 redesign foundation, consolidating the major
CLI, configuration, project-analysis, Markdown-generation, architecture,
safety, testing, tooling, container, CI/CD, and documentation changes developed
after v0.1.0.

This untagged checkpoint prepares the rename of the v0.1.0
`print_project_structure` project to Doc Gen for v1.0.0-rc.1 and transforms its
former four-file project-structure utility into a packaged and
configuration-driven documentation CLI. The new foundation supports
focused generation, printing, and analysis workflows for users while giving
contributors separated scanner, renderer, writer, configuration, CLI,
initialization, UI, and utility components that are easier to understand, test,
debug, maintain, and extend.

### ✨ Features

#### Repository structure workflows

- Added the `doc-gen structure generate [target]` workflow for structured Markdown documentation.
- Added the read-only `doc-gen structure print [target]` workflow for terminal tree output.
- Added the read-only `doc-gen structure analyze [target]` workflow for repository statistics and detected project details.
- Added `doc-gen init` for generating namespaced project configuration.
- Added configurable targets, output paths, depth, file visibility, directory collapse, project type, profiles, smart mode, verbosity, and ignore behavior.
- Added `minimal`, `default`, and `detailed` generation profiles.
- Added smart-mode project inspection that selects appropriate structure settings from repository characteristics.
- Added project detection for common Python and JavaScript-oriented repositories plus generic fallback behavior.

#### Markdown generation and analysis

- Added repository scanning models and services for deterministic directory and file discovery.
- Added structured renderers for repository overview, project tree, root files, directory details, and notes.
- Added a dedicated Markdown writer so rendering and persistence have separate responsibilities.
- Added metadata collection and repository analysis for generated documentation and terminal summaries.
- Added configurable ignore-file loading and built-in exclusions for repositories, environments, caches, dependencies, and build outputs.
- Added explicit output selection while keeping `PROJECT_STRUCTURE.md` as the conventional generated document.

#### CLI, initialization, and configuration

- Replaced direct script execution with a Typer command hierarchy and the `doc-gen` console entry point.
- Added Rich banners, help, panels, tables, progress displays, summaries, and actionable error presentation.
- Added centralized command exception boundaries, unified configuration and structure-domain errors, hidden normal-mode tracebacks, and reliable nonzero failure exits.
- Added shared structure options and consistent CLI → configuration → internal-default resolution.
- Replaced ad hoc defaults with `.config/doc_gen/config.toml` and packaged templates under `app/doc_gen/templates`.
- Added initialization builders, models, registries, presenters, and scaffold-generation services.
- Added configurable console and rotating-file logging.

#### Dry-run safety

- Added `--dry-run` to initialization and every structure command.
- Prevented dry-run initialization from creating directories, writing or overwriting files, or prompting for confirmation.
- Allowed generation dry-run to scan and render in memory while preventing output-directory creation and Markdown persistence.
- Kept print and analyze read-only when `--dry-run` is supplied.
- Added configuration support for dry-run defaults and explicit CLI override behavior.
- Added terminal output that distinguishes generated-document previews from persisted results.

### 🧠 Improvements

#### User experience

- Added explicit command groups that distinguish generating documentation from printing or analyzing a repository.
- Added reusable profiles and smart mode so users can select concise or detailed results without manually setting every option.
- Added clearer target, output, project-type, scan, generation, and summary presentation.
- Added command-specific help and examples for local, Docker, Compose, remote-image, and Make workflows.
- Added documented dry-run guarantees and configuration precedence.

#### Developer experience

- Added modular Make targets for setup, local commands, tests, linting, formatting, QA, documentation, builds, Docker, Compose, remote images, Git helpers, and cleanup.
- Corrected Make option ordering so Typer options are placed before the optional structure target.
- Added development and production Docker images and Docker Compose configurations.
- Added GitHub Actions and GitLab CI definitions for validation, containers, and releases.
- Added setuptools-scm, Ruff, Black, Pytest coverage, MkDocs Material, pre-commit, build, and distribution tooling.
- Added project guidance, contribution, security, licensing, architecture, workflow, and testing documentation.

### 🧠 Refactoring and architecture

- Renamed the project from `print_project_structure` to Doc Gen for the v1.0 release line.
- Introduced `doc-gen` as the installed CLI identity and `app/doc_gen` as the packaged application namespace.
- Replaced the v0.1.0 `print_project_structure.py` implementation with a packaged `app/doc_gen` application.
- Separated Typer commands, options, models, and resolvers from structure-domain workflows.
- Separated scanner, project detector, analyzer, smart-mode, profile, renderer, and writer responsibilities.
- Replaced direct `os`-based traversal and writes with focused services and `pathlib`-oriented models and utilities.
- Added shared configuration builders, result models, domain exceptions, UI components, themes, and logging utilities.
- Separated initialization planning from scaffold persistence and Markdown rendering from file writing to create enforceable dry-run boundaries.
- Added an `AGENTS.md` engineering contract for output safety, dry-run behavior, configuration, tests, documentation, and release safeguards.

### 🐛 Bug fixes and hardening

- Removed hardcoded source paths and output behavior from the original script.
- Replaced broad exception swallowing and direct debug-style printing with structured failures and Rich presentation.
- Corrected virtual-environment, generated-directory, and custom-ignore handling.
- Corrected initialization builder expectations and configuration loading behavior.
- Prevented dry-run generation from invoking the Markdown writer or creating its output directory.
- Prevented dry-run initialization from reaching scaffold persistence.
- Corrected Make, Docker, Compose, and remote-image command ordering for the active Typer hierarchy.
- Aligned `.gitignore`, `.dockerignore`, package metadata, container startup, and project URLs with the current Doc Gen layout.

### 🧪 Tests

- Replaced the untested standalone-script baseline with CLI, configuration, initialization, scanner, generator, renderer, presenter, service, and utility tests.
- Added tests for generate, print, analyze, init, profiles, smart settings, project detection, ignore behavior, output rendering, and command resolution.
- Added regression tests proving initialization dry-run creates no scaffold and generation dry-run never invokes the Markdown writer.
- Added coverage for configuration precedence and dry-run propagation through every structure command.
- Added command-help and developer-workflow validation for local, Docker, Compose, remote-image, and Make entry points.
- Validated the release-candidate baseline with 72 passing tests and 74% measured coverage on Python 3.14.

### 📚 Documentation

- Expanded the README and added installation, configuration, usage, how-to, infrastructure, user, developer, architecture, reference, and testing guides.
- Added a dedicated dry-run guide covering every command, mutation boundaries, configuration precedence, and Make examples.
- Added MkDocs Material navigation and Docker-based documentation builds.
- Added project structure and architecture documentation that explains scanning, rendering, generation, and persistence responsibilities.
- Added local, Docker, Compose, remote-image, and modular Make workflow guidance.

### ⚙️ CI/CD and distribution

- Added Python packaging metadata and the `doc-gen` console entry point.
- Added dynamic package versions from SemVer Git tags through setuptools-scm.
- Added GitHub and GitLab validation and release automation definitions.
- Added development and production container images plus Compose workflows.
- Added reusable quality, package, documentation, and release-support Make targets.

### ⚠️ Breaking changes

- The project is renamed from `print_project_structure` to Doc Gen beginning with v1.0.0-rc.1.
- The former standalone `print_project_structure.py` script is replaced by the installed `doc-gen` command.
- The supported hierarchy is now `doc-gen structure generate`, `doc-gen structure print`, and `doc-gen structure analyze`, plus `doc-gen init`.
- Configuration moves to `.config/doc_gen/config.toml` and uses the current namespaced schema.
- Output generation, terminal printing, and analysis are separate workflows rather than one hardcoded `run()` operation.
- Target and output paths are resolved from CLI/configuration instead of being hardcoded in the script.
- Internal scanner, generator, configuration, and utility imports have changed completely.

BREAKING CHANGE: Doc Gen 1.0 renames the v0.1.0 `print_project_structure`
project and replaces its standalone script with a packaged command hierarchy,
namespaced configuration, explicit output and target selection, profile and
smart-mode behavior, dry-run safety, and layered scanner/renderer/writer
architecture. Existing users must update project references, invocations, and
configuration before adopting the 1.0 release line.
